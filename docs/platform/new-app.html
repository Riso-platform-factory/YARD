new-app: một lệnh, ra app riêng của developer

Developer clone YARD, chạy một lệnh, có app của mình trong application/: tên, identifier, URL scheme, icon của mình, chạy trên cả 3 hệ. App mẫu và engine của YARD giữ nguyên chỗ, nên bản sửa sau này của YARD merge vào không đụng code của developer.

Luồng

Thư mục: của ai

crates/        engine của YARD
extensions/    extension đi kèm (command palette)
app/yard/      app mẫu, giữ làm fixture
examples/      tour, gallery, screenshot
tooling/       cargo xtask, runner checks
docs/  production.json  AGENTS.md  README.md
Cargo.toml     ← trừ mục application, default-members
Cargo.lock     chung; cách merge thuộc upstream-updates
application/   của developer, YARD không bao giờ ghi vào
  Cargo.toml   package/binary: north-star
  build.rs     1 dòng
  product.toml name, version, identifier, url_scheme, icon
  icon.png     icon đưa vào, hoặc ô xám trung tính
  src/main.rs  chạy yard_app với product, extension, menu
  src/menus.rs menu của app
  README.md    chạy, test, đóng gói
  extensions/  extension riêng của developer, về sau

Xanh dương: của YARD, bản cập nhật YARD thay đổi chúng.
Xanh lá: của developer, YARD không bao giờ đụng.
Xám: file sinh ra, hai bên cùng dùng.

  • cargo run chạy app của developer; cargo run -p yard chạy app mẫu.
  • App của developer chỉ dùng code production của YARD. cargo run dev, draft, example vẫn là của app mẫu (cargo run -p yard dev).
  • Luật stage và production.json chỉ áp cho YARD, bỏ qua application/. Luật GPL vẫn áp: app không dùng trực tiếp crate GPL của Zed.
  • Không có --icon: app nhận một ô xám trung tính (không phải icon app mẫu), lệnh báo ở dòng cuối.
  • Version lấy từ product.toml. Tên binary theo tên app: North Star → north-star. Tên gói khi đóng gói giữ như hiện nay (North Star.app, North Star.exe, north-star trên Linux).

Phải sửa YARD trước, vì hôm nay chưa làm được

Build script hôm nay là code production chưa thuộc part nào. Nó chạy trước app nên không thể thử bản mới qua cargo run dev: dời nguyên vào một part, anh duyệt stamp. Đây là ngoại lệ duy nhất của luật "code mới vào dev/". Khởi động là part production đã duyệt: bản mới làm trong dev/ bên cạnh, thay bản cũ khi anh duyệt promote, như mọi lần sửa code production.

Các phần, duyệt lần lượt

#PhầnAnh sẽ thấy khi duyệt
1Build script vào yard_build_configApp mẫu build trước và sau cho cùng giá trị, cùng icon cửa sổ, cùng resource Windows (trên runner); cargo run trace như cũ.
2yard_app: khởi động, kèm examples/north_starcargo run dev: app mẫu khởi động qua yard_app, trace giống cargo run. cargo run -p north_star: tiêu đề, menu About North Star, thư mục, NORTH_STAR_LIFECYCLE đều của North Star.
3cargo xtask bundle --packagebundle macos --package north_star ra North Star.app có menu About North Star, thứ chỉ binary đúng mới có. --dev chỉ cho app mẫu.
4cargo xtask new-appTrong một bản clone mới: chạy lệnh, rồi cargo run ra North Star. Rồi từng trường hợp bị từ chối. examples/north_star bị xoá, app sinh ra thay nó.
5Chạy trên 3 hệ (runner)Checkout riêng: tạo app, đóng gói, cài, mở, mở URL northstar://… trên macOS, Linux, Windows; app mẫu (--package yard) cài cạnh North Star, hai app không đụng nhau ở thư mục, socket, scheme, menu.

Không nằm trong phần này

  • Nhận bản sửa sau này của YARD vào repo của developer: phần kế tiếp, upstream-updates.
  • Đổi tên app mẫu tại chỗ: app mẫu giữ làm fixture của YARD.
  • Chế độ hỏi từng câu của new-app: chỉ có cờ.
